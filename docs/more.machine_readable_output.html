Machine Readable Output

Alongside the HTML, every build writes three files intended for programs rather than
people. They cost nothing to generate and make your documentation usable as data.

llms.txt

Follows the llms.txt convention: a short markdown index naming
every page with a one-line summary, so a language model can find the right page without
crawling the site.

# My Project v1.0

> One line about the project.

Generated by Documon (https://www.documon.net). The API reference below is
derived entirely from source-code comment tags.

## Guides

- [Quick Reference](https://example.com/docs/more.quick_reference.html)
- [Install](https://example.com/docs/more.install.html)

## Reference

- [dirutils](https://example.com/docs/my.dirutils.html): Directory helpers.
- [Menu](https://example.com/docs/my.Menu.html): The navigation tree.

## Optional

- [Full text](https://example.com/docs/llms-full.txt): every page as plain text.
- [Structured model](https://example.com/docs/model.json): the documentation as JSON.

"Guides" is your more folder; "Reference" is what came out of your source comments.
Set --baseUrl to get absolute links; without it the links are relative.

llms-full.txt

The whole manual as plain text — every page, every member, every parameter — in one file.
One fetch instead of dozens, with no HTML to strip.

model.json

The documentation as structured data:

{
  "generator"   : "documon",
  "project"     : "My Project",
  "version"     : "1.0",
  "description" : "One line about the project.",
  "baseUrl"     : "https://example.com/docs",
  "pages" : [
    {
      "id"      : "my.dirutils",
      "name"    : "dirutils",
      "kind"    : "module",
      "package" : "my",
      "description" : "Directory helpers.",
      "file"    : "/dirutils.js",
      "line"    : 12,
      "meta"    : [],
      "members" : [
        {
          "id"      : "my.dirutils.make",
          "kind"    : "method",
          "name"    : "make",
          "type"    : null,
          "access"  : "public",
          "line"    : 40,
          "inherited"   : null,
          "description" : "...",
          "meta"    : [ { "tag" : "since", "label" : "Since", "text" : "1.0" } ],
          "params"  : [
            {
              "name" : "dest", "type" : "string", "description" : "...",
              "optional" : false, "default" : null, "children" : []
            },
            {
              "name" : "opts", "type" : "object", "description" : "...",
              "optional" : true, "default" : null,
              "children" : [
                {
                  "name" : "force", "type" : "boolean", "description" : "...",
                  "optional" : false, "default" : "false", "children" : []
                }
              ]
            }
          ],
          "returns" : { "type" : "boolean", "description" : "..." }
        }
      ]
    }
  ]
}

A parameter documented with a dotted name (@param {boolean} opts.force) becomes a
children entry under its parent rather than a top-level parameter, at any depth.
inherited names the parent an @extends cross-fill came from, and is null for a
member the page declares itself.

Anything that wants to build on your docs — a search index, a linter, an editor plugin, a
coding assistant — should read this rather than scrape the HTML.

Turning them off

documon --no-emitLlms --no-emitModel -i ./src -o ./

Or in documon.json:

{ "emitLlms" : false, "emitModel" : false }
