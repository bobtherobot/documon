Supported Tags

The following flags are processed:

@property, @method, @event

The three basic kinds of entities normally found in a class or module. Example: @property {type} name - description

@package, @namespace

Generally only one per page, but a file may declare several. See the "Package / Namespace" section below. To Documon @package and @namespace are the same thing. They can be used interchangeably, since Documon treats them identically.
Example: @package foo.bar

@class, @module

Both entities are treated equally, but appear in the final rendered docs as "class".
Example: @class name

@private, @protected, @static, @public, @readonly

Items with these flags can be shown/hidden/filtered.
Example @private

@extends

Establishes inheritance. The parent's properties, methods and events are cross-filled
into the child's page, flagged "inherited", and can be toggled in the default template.
This is the only tag that cross-fills. Example: @extends package.Parent

@implements, @inherits

Recorded and rendered as a link in the "meta" section. They do not cross-fill the
parent's members -- only @extends does that. Example: @implements package.Drawable

@overrides

Rarely written by hand: Documon sets it for you when a child redefines a member it
inherited through @extends, and links back to the parent's version. Writing it yourself
also renders a meta link. Example: @overrides package.Parent.method

@requires

Incorporates a list of dependencies that a module or class needs to run. Generally shows up in the "meta" section.
Example @requires package.Class

@constructor

Generally used in conjunction with a class/module, and places a colored tag near the definition.

@example

Multiple examples can exist per item. A nice to have for templating, so the examples can be moved around and they don't have to be hard-coded into the main description. See the "Examples" section below.

@param

Classes, modules and methods can have multiple params. See "Params" section below.

@return, @returns

Can incorporate a {type}.
Example @return {object}

@type

See "Type" section below

@order

By default, everything is sorted alphabetically. Use this flag if you need things to appear in a specific order.
Example: @order 10.4

@header

Used to push a general informational entry to the top of a list. See the "Header" section below.

@default, @defaultVal, @defaultValue

Sets a default value. All three spellings work. The inline form (name=value) is
usually easier -- see Default Values.

@see

Use this to link to similar or related things. See "See Also" below.

Tags from other systems

An unrecognised tag is not a cosmetic problem in Documon -- structure comes only from
tags, so a tag it can't read costs the whole entity, not just the line. The common
spellings from other documentation systems are therefore accepted as exact synonyms:

written read as
@function, @func @method
@arg, @argument, @parameter @param
@prop, @member, @var @property
@augments @extends
@yields, @yield @return
@constructs @constructor
@defaultvalue @default
@const, @constant a read-only @property
@access private @private (also protected, public)

Description tags — @desc, @description, @summary, @classdesc, @fileoverview,
@file, @overview — are folded into the block description, and inline [target](target)
becomes a markdown link.

@deprecated, @throws/@exception, @since, @author, @license, @copyright and
@todo have no structural role, but are rendered as metadata rows on the member rather
than discarded.

Tags that are deliberately not accepted

These look like they should map onto something, but their meaning differs. Aliasing them
would produce documentation that is quietly wrong, so Documon leaves them alone and
--check explains each one instead:

tag why not
@fires, @emits Documents which event a method emits. @event declares the event itself. Document the event separately and mention it in the description.
@memberof Re-parents an entity. Documon scopes by @package plus the enclosing @class/@module.
@typedef Documon has no type registry. Describe the shape in the description, or document it as a @class.
@callback Document it as a @method, or describe the signature in the @param description.
@enum Document each value as a @property.
@inheritdoc Use @extends; Documon cross-fills inherited members automatically.

Run documon --check to see exactly what was normalized or ignored.

Retired spellings

@impliments was Documon's own misspelling of @implements. It was retired in v3.0.0
rather than kept as a silent alias, so the typo doesn't propagate into new projects.
documon --check reports it by name and tells you what to rename it to.
